# 来客受付・入退館記録

## 概要

社員50〜150人のオフィスを想定した来客受付アプリです。社員が来訪を予約し、来訪者がタブレットで受付。入館証の貸出から退館・返却までを記録します。あおぞらシステムズ 本社（架空）を舞台にした、日本語のポートフォリオ作品です。

## 主な機能

### 来訪予約

来訪日・予定時刻、会社名・氏名・人数・同行者、担当者、目的、案内先、メモを登録・編集・取消できます。重複しない4桁の受付番号を発行し、受付済みの記録は予約編集から保護します。

### 受付用タブレット画面

`/kiosk` は社員用ナビゲーションのない全画面です。数字キーパッドで受付番号を入力するほか、お名前・会社名による本日の予約検索、予約なしの来訪に対応。候補と確認画面は氏名・会社名の一部を伏せ、60秒無操作で入力内容を消して最初の画面に戻ります。担当者が不明な場合は総務を選択できます。

### 入館・退館の記録

受付時に現在の日本時間と空いている入館証を記録します。入館証は1組につき1枚、返却まで再貸出しません。退館は入館証番号または受付番号で検索し、返却を確認して記録。社員側では未返却のまま退館を記録し、後から返却処理もできます。期間・担当者・会社による履歴検索とBOM付きCSV出力に対応しています。

### 担当者への来訪通知（画面内）

受付すると通知ベルに未読件数を表示します。「対応します」で対応者と対応時刻を記録。同じオリジン・同じブラウザの別タブには `storage` イベントで即時反映します。Web Locks APIを利用できる環境では更新を直列化し、同時受付による入館証の二重割当を防ぎます。

5分以上未対応の通知は強調され、受付端末では総務への取次ぎ案内に切り替わります。担当者が対応すると「担当者が向かっています」と表示。60秒の自動リセット後も、「お帰りの方・お呼び出し状況」から入館証番号で再確認できます。総務への取次ぎは画面内の表示のみで、外部通知は送信しません。

## 日時の扱い

- すべて日本時間（JST）。日付は `YYYY-MM-DD`、予定時刻は `HH:MM`、実績は日本時間の `YYYY-MM-DDTHH:MM:SS` 文字列として保存します。
- 「今日」と「現在時刻」はクライアントのマウント後に決め、15秒ごとに表示を更新します。サーバー描画時に日時やlocalStorageを参照しません。
- 初回と既定データへのリセット時に、開いた日時から過去約60日分の履歴を生成します。実績・通知は必ず生成時点より前です。
- 営業日は曜日に応じて4〜8件の予約を用意します。予定を過ぎた来訪は1件を未到着とし、残りは入館済み。用件に応じた退館予定が現在より前なら退館済みにします。未来の予定は未受付です。
- 0〜5時台・23時台と土日祝・年末年始（12月29日〜1月3日）は本日の予約なし。夜間や休日に館内の人を無理に残さず、未返却履歴と未読通知は確認できます。祝日・振替休日・国民の休日も除外します。
- 既存の保存データは翌日も保持します。デモをその日の状況に合わせて作り直すには「このデモについて」から既定データに戻してください。

| 作品             | 主に扱うもの                           | 本作で扱うもの                                   |

## データの保存先

localStorageのキー `vrl:v1` に保存します。**同じブラウザ内のみ**で共有され、異なるブラウザ・端末・オリジンには反映されません。実運用では受付端末と社員端末の共有にサーバーが必要です。認証・アクセス制御はなく、受付画面の分離はセキュリティ境界ではありません。

読み込み時に型・日付・参照先・番号重複・入退館順序・通知との整合性を検証します。保存データが壊れている場合は既定データへ復旧し通知します。JSONインポートの不正データは拒否し、現在の記録を保ちます。復元・初期化は内容を画面で確認してから実行します。ブラウザのサイトデータ削除で記録も削除されるため、必要な記録はJSONで保存してください。

## 技術スタック

- Next.js 16 / App Router / TypeScript / React 19
- Tailwind CSS 4の既存環境、画面別に分割したCSS
- localStorage / storageイベント / Web Locks API
- Node.js標準テストランナーと既存のTypeScriptによるメモリ内変換（追加テストパッケージ不要）
- ESLint、Prettier（printWidth: 100）
- PWA manifest、192px・512pxアイコン、本番のみ登録するService Worker

Service Workerは静的アセットをキャッシュし、オフライン再訪時には接続確認ページを表示します。来訪データはCache APIに保存しません。完全なオフライン再起動を保証するものではありません。外部Webフォントは使いません。

純粋関数は `src/lib/`、画面と共通部品は `src/components/`、ルート定義は `src/app/`、テストは `tests/` に分離しています。

## ローカル起動方法

Node.js 24以降を使用し、すべてのコマンドを `visitor-reception-log` 直下で実行してください。

```powershell
npm install
npm run dev
```

http://localhost:3000 を開きます。同じブラウザの別タブで `/kiosk` を開くと、受付と担当者対応の連動を確認できます。

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

整形は次のコマンドです。Prettierは依存関係に追加していません。

```powershell
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

### 静的配信での予約詳細

通常の `npm run build` / `npm start` は任意の `/visits/[id]` に対応します。詳細データはクライアントでURLとlocalStorageから読み取るため、新規追加した予約も開けます。

`output: "export"` で静的書き出しする場合、Next.jsはビルド時に未知のIDのHTMLを生成できません。`/visits/detail` を共通の静的入口として用意しています。静的ホスト側で `/visits/*` を `/visits/detail.html` へ内部フォールバックしてください（URLは保持）。また、生成した `404.html` をカスタム404として配信すれば、詳細画面はそのURLから復元できます。静的ホストで単純なファイル未検出を返すだけの設定では未知IDを直接開けません。

`turbopack.root: process.cwd()` はこのフォルダに維持してください。ルートレイアウトのSuspenseやcacheComponentsは使用していません。

## デモデータについて

すべて架空で、日付は開いた日からの相対です。実在の企業・個人とは無関係です。社員12名、案内先5つ、入館証V-01〜V-20、過去約2か月の来訪履歴約100件と当日の予約を用意しています。

来訪者は30名。継続取引の16名と、面接・営業訪問・見学など一度だけの14名を混ぜています。常連は約10日ごとの営業日に来訪し、当日分も含め月4回を上限にしています（集計期間の端の月は少なくなります）。会社ごとに担当者を固定し、同行者は会社別で、多くの回は単独来訪です。

予約は00・15・30・45分が中心で、一部は半端な時刻。入館は予約の5分前〜10分後、滞在は納品10〜20分、打合せ40〜120分、面接50〜70分、工事120〜240分、見学等30〜90分です。予約なし来訪は各月2〜3件。退館打刻の補記と入館証持ち帰りを各1件含み、同時滞在中・未返却の入館証は再利用しません。

メモは約4割にだけ付け、重複する文や日時の前置きはありません。同じ基準日なら予約と履歴を再現でき、基準日を変えると時刻や来訪日が変わります。シードのテストでは指定日時を含む24通りの日時で、実績・通知の時系列、頻度、メモ、担当者、貸出履歴などを確認します。
